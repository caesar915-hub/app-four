# Android Port — Execution Plan (v1.1)

**Basis.** Every technical choice below is grounded in the deep verification report ([ANDROID_PORT_FEASIBILITY.md](ANDROID_PORT_FEASIBILITY.md), 2026-07-21, source-linked). No claim here is carried over from the original study unverified. **Deep-reviewed 2026-07-21 23:33 by 5 independent web/repo fact-check agents**; 2 refutations + 8 material gaps corrected in this v1.1 (marked ⟲).

**Explicit scope rulings (owner, 2026-07-21):**
- **Sync (spec 038) is OUT OF SCOPE.** Android v1 is standalone, local-only. One zero-cost hedge stands anyway: keep the `JournalArchive` export format versioned — it is the future interchange path whatever the eventual sync posture. ⟲ Already true today: `formatVersion` field, `currentFormatVersion = 1` ([ExportService.swift:11-18](../app-four/Services/ExportService.swift#L11)) — the hedge is "keep", not "add".
- Also out of scope for v1: widgets / Live Activities (no Android equivalent of 037), App Intents surface (030), hands-free, TestFlight-style stable channel.
- **In scope (the core loop):** record → transcribe on-device → extract signals → journal entry → calendar/day view → recording detail → basic settings.

**Route (decided, per report §7):** **Skip Fuse** — the shared Swift core compiles *natively* for Android on the official Swift 6.3 SDK; SwiftUI maps to Compose via SkipFuseUI → SkipUI (SkipBridge is the JNI interop layer, not the UI mapper — [skip.dev/docs/modules/skip-bridge](https://skip.dev/docs/modules/skip-bridge/)). Option B (C++/Rust core) is rejected: both of its justifications were disproven. Solo dev + AI agent; all estimates assume that pairing. ⟲ Skip status as verified 2026-07-21: **v1.9.4 (2026-06-26), fully free/OSS since 1.7 (2026-01-22)** — no license cost line anywhere in this plan ([skip.dev/pricing](https://skip.dev/pricing/), [skip.dev/blog/skip-is-free](https://skip.dev/blog/skip-is-free/)); docs live at **skip.dev** (skip.tools redirects); `skip.yml` still *defaults to transpiled mode* — Fuse must be set explicitly ([modes doc](https://skip.dev/docs/modes/)); scaffold via `skip init`'s generated Gradle project, not a hand-rolled AGP shell.

## Phase 1 — Foundation (3 weeks)

1. **Shared-core extraction (SPM).** Pull the platform-neutral Swift into packages consumable by both apps: `SquirlSignals` (already a package), `NoteExtraction` + lexicon + inflection table, model value-types (DTOs mirroring the SwiftData models), design tokens from `SquirlDesignSystem`. SwiftData `@Model` classes stay iOS-only; the shared layer speaks DTOs. (Repo already on Xcode 16 synchronized folders — file moves are low-friction; no project-generation tooling.)
2. **Android app scaffold.** Gradle/AGP project, Skip Fuse integration, CI job that cross-compiles the Swift core and assembles a debug APK on every push. `pickFirsts` for `libc++_shared.so` from day one.
3. **Persistence layer** (if P0.3 picked Room; else SkipSQL schema, same inventory). Full schema from the *real* model (⟲ **29 `Recording` stored fields, 3 relationships** — counted from [Recording.swift](../app-four/Models/Recording.swift#L9), correcting v1's "21/4" which appears nowhere in the report; report §6's "14 studied + 15 omitted, 1 + 2 cascade relationships" reconciles to the same 29/3): `@Upsert` (never `REPLACE`+CASCADE), `@Index` on every FK child column, Date↔Long converters, `@Relation` results explicitly sorted by `startTime`. Migration story: none needed (v1 greenfield), but schema versioned from 1.
4. **Audio capture.** `AudioRecord` 16 kHz mono PCM pipeline + AAC encode via MediaCodec **⟲ + `MediaMuxer` (MUXER_OUTPUT_MPEG_4)** for the stored artifact — MediaCodec alone emits a raw AAC elementary stream, not a playable .m4a. ⟲ Float-PCM caveat: encoder float input requires `KEY_PCM_ENCODING = ENCODING_PCM_FLOAT` *confirmed via `getInputFormat()`* and is not guaranteed per device — fall back to 16-bit PCM into the encoder. Android 14+ foreground-service-type `microphone` compliance (`FOREGROUND_SERVICE_MICROPHONE` + granted `RECORD_AUDIO`; cannot start from background — [FGS types doc](https://developer.android.com/develop/background-work/services/fgs/service-types)); interruption handling (calls, focus loss).

## Phase 2 — Core loop (4 weeks)

5. **STT integration** (P0.2 winner): JNI bridge written to the audited standard — `_with_params` init, mutex-guarded context handle, null checks, errors thrown to Kotlin (never `""`), transcript returned as UTF-8 `jbyteArray` (not `NewStringUTF`), direct ByteBuffer for PCM, thread count left to library default. Vocabulary injection per engine (initial_prompt / hotwords). Model delivery: bundle the winning model in an **install-time Play asset pack** — ⟲ current limits ([Play size doc](https://support.google.com/googleplay/android-developer/answer/9859372)): 500 MB base module, 1.5 GB per asset pack, **4 GB cumulative install-time**; whisper-small q8_0 = 264 MB fits easily, Parakeet int8 ≈640 MB exceeds the base cap so the asset pack is mandatory for it. Explicit unload API mirroring iOS `unloadModel()` ([WhisperKitTranscriptionService.swift:216](../app-four/Services/WhisperKit/WhisperKitTranscriptionService.swift#L216)).
6. **Extractor wired end-to-end**: transcript → shared Swift extractor (native, via Fuse) → DTO → Room. Golden-fixture suite runs in Android CI on every commit — this *is* the parity guarantee that Option B's rewrite was supposed to buy.
7. **UI build-out** (SkipFuseUI, DESIGN.md as source of truth): check-in flow → day card/calendar → recording detail (027 layout) → settings (minimal). HTML-mockup-first rule applies per screen where the Android layout diverges from iOS.

## Phase 3 — Hardening → closed beta (3 weeks)

8. Error surfaces + empty/edge states; thermal/battery guardrails (abort + preserve audio on thermal pressure); TalkBack/accessibility pass; large-file and storage-pressure behavior.
9. **Test strategy** (no XCTest carry-over exists on Android): shared-core logic tested by the fixture suite + `swift test` on host; Android-side JUnit/Compose tests for DB, audio, and navigation; on-device smoke checklist mirroring the iOS QA rounds.
10. Play readiness: data-safety form ("no data collected" is truthful for on-device-only processing, but the form + a privacy-policy link are mandatory regardless — [data safety doc](https://support.google.com/googleplay/android-developer/answer/10787469)); ⟲ **Health apps declaration** (mandatory for all apps since 2024-08-31; "managing medication schedules/adherence" and mental-health tools are listed health features — this app cannot honestly tick "none", [health apps doc](https://support.google.com/googleplay/android-developer/answer/14738291)); final 16 KB re-verification (primary gate moved to P0.1); min SDK 28, ⟲ **targetSdk 36** (required for new apps from 2026-08-31 — [target-API doc](https://developer.android.com/google/play/requirements/target-sdk)); ⟲ closed-testing track + **12 testers opted-in for 14 consecutive days** (personal accounts created after 2023-11-13 — [Play doc](https://support.google.com/googleplay/android-developer/answer/14151465)), not "~10".

## Budget & risks

- **Timeline: ~12 weeks** (2 + 3 + 4 + 3) solo-dev + agent, *conditional on G0*. Uncertainty is front-loaded by design — the two unknowns that can void the whole plan (STT RTF, Fuse fidelity) are resolved in week 1–2 for ~9 days of effort.
- **Top risks, in order:** (1) STT quality/latency on mid-tier hardware — gated at P0.2; (2) SkipFuseUI coverage gaps for Squirl's custom visuals (signal glyphs, meadow ramps) — surfaced at P0.3, fallback is per-screen Compose; (3) Swift-on-Android toolchain maturity (no platform owner; Deployment-tier only) — accepted, mitigated by pinning toolchain versions in CI; (4) model download/storage UX (install-time pack needs ~2× free space at install).
- **Deliberately deferred:** sync (038 ruling will define it — revisit as "Android v2" scope), widgets/Intents surfaces, tablet layouts, additional languages beyond the STT engine's validated set.

**Standing recommendation unchanged:** this plan is *ready to execute*, but execution should start when there is an Android demand signal post-1.0. Phase 0 is cheap enough (~2 weeks) to run early as insurance if the team prefers.
