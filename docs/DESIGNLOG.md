# app-four DesignLog

Chronological record of **design-artifact work that git cannot see** — Figma / Penpot reproductions, design-system boards, component libraries, mockups, and hi-fi screens built in cloud design tools. Newest block on top.

**Why this file exists.** [WORKLOG.md](WORKLOG.md) is regenerated from `git log` (`scripts/worklog.sh`), so it only records work that produced commits. Design output lives in the cloud (Figma file `M0Meys9X89X1NLyT14qrX5` "Squil-Design", hosted Penpot) and produces no repo artifact — WORKLOG is structurally blind to it. This is the "what changed / when" record for that work, the counterpart to WORKLOG.

**Division of labour** (don't duplicate across files):
- **DESIGNLOG** (this file) — *what design artifact was produced, where (file/page/node IDs), and when.* The manifest + index. Node-ID inventories live here, not in DEVLOG/BACKLOG.
- **[DEVLOG.md](DEVLOG.md)** — the *why* behind the work. Design entries there stay brief and link here.
- **[BACKLOG.md](BACKLOG.md)** — the *stage* (💡→📐→🔨→✅) of each item.
- **[DESIGN.md](../DESIGN.md)** — the source of truth for Squirl's own visual decisions (a spec, not a log).
- **`docs/ui/reference/*`** — measured teardowns of reproduced apps (the durable measurement record).

**Entry format** — one block per design session, newest on top:
```
## [YYYY-MM-DD HH:MM TZ] <Tool> — <artifact> in <file/page> (`node-id`)
- **Built:** <components / screens / boards, with node IDs>
- **Source:** <screenshots / code / reference>
- **Verification:** <screenshot QA, pixel audits, review agents>
- **Stand-ins / caveats:** <font substitutions, approximations>
- **Links:** teardown doc · DEVLOG entry (why) · BACKLOG stage
```
Stamp the real clock (`date "+%Y-%m-%d %H:%M %Z"`); bump the header `Updated:` on every edit. Reproductions are **reference studies** — nothing migrates into Squirl without going through DESIGN.md.
