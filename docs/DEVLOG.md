## 2026-06-18

- **Investigation** — Core ML text-classification spike (mood/energy/focus) — **outcome: pipeline viable on device, models not.** Trained 3 Create ML BERT-embedding classifiers on a synthetic corpus; rebuilt the corpus (cross-domain negatives, negation→level, ~50% `none`) and retrained via a reproducible CLI toolchain (`spikes/createml-nlmodel/{rebuild_corpus,train,predict,eval_ml}.{py,swift}`). **Two separable findings:** (1) *Deployment works* — models run on the iPhone 12 Pro (`NLContextualEmbedding.hasAvailableAssets=true`); they are **dead on the Simulator** (asset absent → `NLModel` returns nil → silent lexicon fallback). (2) *Quality fails* — on the 40-case EvalSet the ML path scored **mood P=0.27, energy P=0.00, focus P=0.04**, far below the lexicon floors (0.73/0.65/0.38). Clean single-sentence probes looked great but lied; real multi-sentence transcripts compound cross-domain false positives, and "strongest-sentence-wins" aggregation surfaces the worst one. **Root cause = synthetic training data + no abstain calibration, not Core ML/BERT.** Reverted the `NLSummarizationService` wiring back to pure `NLNoteExtractor` (the ML override would regress all three signals on a device build). · *why:* the EvalSet number — not probe spot-checks — is the only valid gate; it exposed the spike as non-viable as-built · branch `spike/ml-signal-extractor-DO-NOT-MERGE` (do not merge) · next if pursued: real labeled transcripts + aggressive `none` coverage + rethink aggregation.
