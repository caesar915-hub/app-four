The matching primitive

Every category routes through CueMatcher.contains. Multi-word cues need a contiguous surface run; single-word cues get two extra escape hatches.

flowchart TD
    A["cue vs sentence tokens"] --> B{"cue token count"}
    B -->|multi-word| C["contiguous run of surfaces<br/>must match exactly"]
    B -->|single word| D{"surface == cue?"}
    D -->|yes| E["MATCH"]
    D -->|no| F{"surface in cue.altForms?"}
    F -->|yes| E
    F -->|no| G{"cue.lemma != nil AND<br/>token.verbLemma == cue.lemma?"}
    G -->|yes| E
    G -->|no| H["NO MATCH"]
    C -->|found| E
    C -->|not found| H

CueMatcher.swift:175-199

Dead path: canonicalInflections is an empty dictionary (CueMatcher.swift:124), so altForms is always []. That table was the simulator-safe route — the verb-lemma bridge rides NLTagger's lemma model, which the code comments say is absent on the iOS simulator.

Signal resolution policies

FIG 05

Medication extraction

Name matching is unanchored substring search over 89 lexicon names, with an edit-distance-1 typo fallback that exists because the input is speech-transcribed. Note the scope split: attributes come from the clause, but taken/not-taken comes from the whole sentence.

FIG 06

Lexicon loading — the silent fallback

All 32 LexiconData properties are non-optional with no defaults, so one missing key aborts the whole decode and silently drops the app to the smaller compiled defaults (medications 89 → 56). No throw, no log, no flag.
