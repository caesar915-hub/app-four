# 11 · Non-Functional Requirements

Documents branch `main` @ `43eb6515a63a0eca957a79aad257da380c73edd4`. Sibling documents: [Settings & Data Management](08-settings-and-data.md) · [Data Model](09-data-model.md) · [Architecture & Services](10-architecture-and-services.md).

## Purpose

Capture the quality attributes of Squirl 1.0 as numbered, verifiable requirements. Each NFR is tagged:

- **[Implemented]** — verified in code on `main` (citation given).
- **[Committed]** — a documented product/design commitment (`PRODUCT.md`, `DESIGN.md`) that is only partially evidenced in code, or a design target for a future release.
- **[Gap]** — commitment and implementation disagree; the disagreement is documented and owner-accepted.

## Scope

Accessibility, privacy & security, performance, reliability, localization readiness, and platform compatibility. Functional behavior lives in the sibling documents; this file constrains *how well* the system does it.

## Accessibility

- NFR-01 **[Committed]** WCAG 2.1/2.2 AA is the hard floor: contrast ≥ 4.5:1 for body text, ≥ 3:1 for large text and UI components; touch targets ≥ 44×44 pt; VoiceOver labels on all controls; Dynamic Type AX1–AX5; Reduce Motion fallbacks ("breathing/rotation collapse to static"). (`PRODUCT.md` §Accessibility & Inclusion)
- NFR-02 **[Implemented]** Minimum tap target is a design-system token, `Metrics.minTapTarget = 44` pt, applied to interactive controls (e.g. check-in hub pills, calendar header button, model-row ghost pills). (`Packages/SquirlDesignSystem/Sources/SquirlDesignSystem/Metrics.swift:10`; `CheckInView.swift:225-238`; `ModelDownloadRow.swift:110-143`)
- NFR-03 **[Implemented]** Color is never the only cue: every signal level is encoded by glyph shape + fill + hue simultaneously ("a shape ladder, never opacity alone"), verified grayscale/colorblind-safe via silhouette test. (`PRODUCT.md` principle 5; `DESIGN.md` §Iconography; `SquirlDesignSystem/Glyphs/`)
- NFR-04 **[Implemented]** VoiceOver support in the capture flow: the recording timer is an accessibility element with `.updatesFrequently`, throttled to whole seconds so VoiceOver doesn't chatter; prompt changes announce `"<question> <hint>"` only when the user is not speaking (active-voice threshold 0.1, announcements coalesced to a single pending flag); state changes announce `"Saving…"` / `"Captured."`. Decorative elements (crescent, progress bar, prompt dots) are `accessibilityHidden`. (`CheckInView.swift:61-66`, `:147-162`, `:263-270`; `CheckInViewModel.swift:49-66`)
- NFR-05 **[Implemented]** Reduce Motion is honored throughout: all `CrescentRing` animations removed (`reduceMotion ? nil : …`); check-in state transitions, saved-check spring, calendar expand/collapse, title-band fade, transcript toggle, and chevron rotations are gated on `accessibilityReduceMotion`; the medication bar's onset pulse (fill opacity dip to 0.55, 1.3 s repeating) never runs under Reduce Motion and stops live if the setting toggles; bar progress animation (0.5 s easeInOut) is likewise skipped. (`CrescentRing.swift`; `CheckInView.swift:29,134-136`; `05-medications` notes, `MedicationBarView` lines 141-172; `03-library-calendar` notes §Reduce Motion)
- NFR-06 **[Implemented]** Dynamic Type: every typography role is `UIFontMetrics`-scaled (SF Pro/Mono); layout adapts at large sizes — model-row ghost pills reflow via `FlowLayout`, the onboarding screen keeps the hero and Start button reachable at AX5 via `ScrollView` + `minHeight`, and content is capped at `Metrics.maxContentWidth` (600 pt). (`Typography.swift`; `WelcomeView.swift:23-31`; `ModelDownloadRow.swift:110-143`)
- NFR-07 **[Gap]** Documented, owner-accepted contrast exceptions (Figma-fidelity rulings): `NewLook.inkSecondary` `#8A8A8E` measures 3.0:1 on `screen` / 3.4:1 on `card` in light mode (below the 4.5:1 body floor; dark mode passes ~7:1); `NewLook.selection` `#54B492` measures 2.52:1 on white (chip labels, green-on-card text, ramp selection ring); dose-track gradient end `#AF99C3` is 2.14:1 against its groove; muted ink `#7A7361` fails AA for small text on paper (use ≥ large/bold or darken to ~`#6A6354`); meadow amber is decorative-only, never text. These are logged limitations, not bugs; revisit requires explicit approval. (`DESIGN.md` palette notes, decisions 2026-07-12/16; `PRODUCT.md` §Accessibility)
- NFR-08 **[Gap]** The medical-prompt opt-out (`UserDefaults.medicalPromptEnabled`, default ON) is honored by the transcription actor but has **no visible Settings toggle** on main, despite the code comment placing it in "Settings → Accessibility". Users who need non-medical vocabulary cannot reach the switch in the UI. ([Settings](08-settings-and-data.md) FR-SET-18)
- NFR-09 **[Implemented]** No shame mechanics by design: no streaks, badges, gamification, confetti, red "you're late" alarms — a worn-off dose "just goes quiet" (medication bar fades out). Cap-approach cue is faint, red-free, and non-ticking. (`PRODUCT.md` §Anti-references; `DESIGN.md` §Product Posture; `CheckInView.swift:293-299`)

## Privacy & security

- NFR-10 **[Implemented]** Everything is on-device: transcription (WhisperKit, `requiresOnDeviceRecognition` on the legacy path), extraction (rule/lexicon-based NaturalLanguage, "no LLM, no model download"), storage, and summarization. No account, no server, no backend — "the app has no backend and the prompt explicitly forbids auto-upload" (MetricManager comment). (`PRODUCT.md` §Product Purpose; `02-extraction-ai` notes; `MetricManager.swift:5-25`)
- NFR-11 **[Implemented]** All user data lives under `Application Support/SquirlData/` — never `Documents` — so it is invisible to the Files app and Finder/iTunes file sharing: recordings, exports, diagnostics, and the SwiftData store. (`AppPaths.swift:3-20`)
- NFR-12 **[Implemented]** The SwiftData store directory and the entire `SquirlData` subtree are flagged `isExcludedFromBackup`, keeping transcript and medication data out of iCloud/device backups. (`AppModelContainer.swift:28-30`; `AppPaths.swift:11-16`)
- NFR-13 **[Implemented]** The privacy manifest `app-four/PrivacyInfo.xcprivacy` declares `NSPrivacyTracking = false`, an empty `NSPrivacyCollectedDataTypes` array, and exactly three accessed-API categories with reasons: FileTimestamp (C617.1), UserDefaults (CA92.1), DiskSpace (E174.1). (`PrivacyInfo.xcprivacy`)
- NFR-14 **[Implemented]** Journal export is encrypted end-to-end: fresh AES-256-GCM key per export (CryptoKit CSPRNG), never persisted (no Keychain/UserDefaults/file), combined blob (nonce + ciphertext + tag); the plaintext archive never touches disk unsealed; clipboard copies are `.localOnly` with 120 s expiry. The export is write-only — no import path exists. Info.plist declares `ITSAppUsesNonExemptEncryption = false` (exempt encryption). ([Settings](08-settings-and-data.md) FR-SET-26…29, FR-SET-36…39; `app-four/Info.plist`)
- NFR-15 **[Implemented]** Diagnostics are content-free by construction: `SessionSnapshot` never includes transcript text, summary text, or audio file paths; `ModelDownloadFailure` "names the *condition*, never any transcript or medication data (Principle VI)". MetricKit payloads are only logged locally — no upload. Sensitive-data toggles in the (dormant) issue report default OFF. (`SessionSnapshot.swift:8-59`; `Protocols.swift:142-147`; `IssueReportView.swift:14-17`)
- NFR-16 **[Implemented]** Medication discretion: the "Name medication in confirmations" setting defaults OFF so banners/spoken/lock-screen confirmations never name a drug unless the user opts in; guarded-copy names the earlier dose's *time*, never the drug. (Note: the toggle's settings UI is currently dormant — [Settings](08-settings-and-data.md) FR-SET-34; the underlying `AppSettings.nameMedicationInConfirmations` flag and copy logic are live, consumed by `DoseLogService`.) (`DoseConfirmationCopy.swift:3-25`)
- NFR-17 **[Committed]** Health-adjacent honesty: the app presents itself as "a personal journal, not medical advice" with manufacturer-typical dose/effect values (App Review 1.4.1 disclaimer, mounted in Settings). (`MedicalInfoSection.swift:9-15`)

## Performance

- NFR-18 **[Implemented]** Audio capture is bounded: hard cap 480 s (8 min) enforced twice — the view-model timer (0.1 s tick) and a service-level backstop polling every 100 ms; a one-shot cap-approach cue fires at ≥ 450 s. Format: AAC `.m4a`, 16 kHz, mono, high quality. (`Constants.swift:10`; `CheckInViewModel.swift:441-457`; `AudioRecordingServiceImpl.swift:14-19`, `:251-262`)
- NFR-19 **[Implemented]** Pre-flight resource gates: recording refuses to start below 50 MB free (`50 * 1024 * 1024`, view-model gate) with a 20,000,000-byte service backstop; export refuses archives whose summed audio exceeds 200 MiB (`200 * 1_024 * 1_024`) because the whole archive is buffered in memory (≈ 3–4× raw audio) — protecting the A14 minimum target from an uncatchable OOM. (`Constants.swift:11`; `AudioRecordingServiceImpl.swift:60`; `ExportService.swift:142-149`)
- NFR-20 **[Implemented]** The Whisper model is unloaded at the end of every transcription (success or error) so Metal/CoreML buffers are freed before NL extraction; concurrent loads coalesce via a shared task; compute units are `.cpuAndNeuralEngine` for distribution-signed builds (TestFlight/App Store), `.cpuAndGPU` on Simulator and development-signed builds (embedded `embedded.mobileprovision` ⇒ developer-tunnel launches where the ANE compiler is unreachable). (`WhisperKitTranscriptionService.swift:48-81`, `:163-219`; `ComputeEnvironment.swift`)
- NFR-21 **[Implemented]** Single-inference discipline: the shared WhisperKit actor cancels any prior transcription before starting a new one, and the capture flow chains a new transcription after the prior completes — the engine never runs two inferences at once. Transcription is capped by a 90 s timeout and holds a `UIApplication.beginBackgroundTask` for the whole inference. (`WhisperKitTranscriptionService.swift:97`; `CheckInViewModel.swift:164-167`, `:247-250`)
- NFR-22 **[Implemented]** Polling cadences are fixed and modest: audio level sampling every 50 ms while recording; UI timer at 0.1 s; audio-player progress polling every 250 ms while playing (cancelled on pause/finish/disappear). The medication bar has **no timer** — progress recomputes only on appear and on `.medicationEventsDidChange`. (`AudioRecordingServiceImpl.swift:43`; `CheckInViewModel.swift:449`; `03-library-calendar` notes, audio-player lines 82-95; `05-medications` notes line 186)
- NFR-23 **[Implemented]** Query budget: the medication bar fetches the last 24 h of events (`now - 24 * 3600`) with `fetchLimit = 50`; med-name history fetches with `fetchLimit = 100`; diagnostics keep a rolling buffer of 50 snapshots as a plain JSON file (not SwiftData) to keep I/O off the main actor. (`05-medications` notes lines 60, 66; `MedicationPickerViewModel` line 59; `DiagnosticsStore.swift:8-9`)
- NFR-24 **[Implemented]** Known scaling bound: dose-ordinal counting pools from the last-24h/limit-50 fetch, so > 50 medication events in 24 h could miscount the ordinal. (`05-medications` notes line 382)
- NFR-25 **[Committed]** North-star responsiveness: a check-in completes "in under a minute", and the Saved state shows no transcribing UI — transcription/extraction run silently in the background so capture never waits on inference. (`PRODUCT.md` §Product Purpose; `DESIGN.md` decisions 2026-06-15)

## Reliability

- NFR-26 **[Implemented]** Launch never crashes on store failure: the recovery ladder is DEBUG wipe-and-retry → (release) readable-but-unopenable → quarantine store trio (rename, never delete; pending marker committed first; sidecars before the database) → retry → undo-quarantine on failure → last-resort in-memory container with `isEphemeral = true` (`try!` justified as impossible on a valid schema). A crash/jetsam mid-quarantine is self-healed on next launch via `recoverInterruptedQuarantine`. "On-disk data is untouched or quarantined — never deleted in release." ([Data Model](09-data-model.md) FR-DAT-04…07)
- NFR-27 **[Implemented]** A data-protection-locked store (pre-unlock background launch) is distinguished from corruption and left untouched, degrading to ephemeral mode rather than quarantining healthy data. (`AppModelContainer.swift:56-63`, `:140-145`)
- NFR-28 **[Implemented]** Orphan-status recovery at launch: recordings stuck in `.transcribing` flip to `.failed` with calm retry copy (`"Transcription was interrupted. Tap to retry in the recording detail view."`); `.pendingTranscription` recordings are never swept — they drain through the identical transcribe→summarize path once the model lands (launch, foreground, and download-completion triggers; `isDraining` latch). ([Data Model](09-data-model.md) FR-DAT-13; `PendingTranscriptionServiceImpl.swift:37-82`)
- NFR-29 **[Implemented]** Save-failure retry (PendingSave): on persistence failure the just-recorded audio URL + duration are buffered and the UI offers inline "Try again" / "Discard" — never a silent reset; text check-ins keep the draft intact in the composer on failure. Onboarding completion swallows save failure so the user is never stranded on an undismissable cover. (`CheckInViewModel.swift:39-47`, `:215-244`, `:411-439`; `WelcomeViewModel.swift:21-30`)
- NFR-30 **[Implemented]** Audio interruptions never lose a recording: the interruption handler only pauses/resumes (never stops/cancels), with a pure testable policy (`pause`/`resume`/`stayPaused`/`ignore`); the service's duration bookkeeping excludes the paused span. (`AudioRecordingServiceImpl.swift:160-249`)
- NFR-31 **[Implemented]** Pre-1.0 storage migration is one-time, idempotent, and non-destructive: file-by-file, newer-mtime wins, legacy items moved aside as `<name>.legacy`, directories removed only when empty — "a failed move never deletes an un-migrated file." (`StorageMigration.swift:34-72`)
- NFR-32 **[Implemented]** Dose logging fails closed: when dose history is unreadable while a guard is armed, or a save fails, the outcome is `.failed` ("Couldn't save that dose — nothing was logged. Try again in the app.") — always safe to retry, never a partial write presented as success. (`DoseLogService.swift:5-16`; `DoseConfirmationCopy.swift:19`)

## Localization readiness

- NFR-33 **[Gap]** The app ships English-only: user-facing strings are hard-coded literals throughout (no `.xcstrings` catalog, no `.strings` files, no `.lproj` directories exist on main), and Whisper decoding is hard-coded `language: "en"`. `AppSettings.defaultLanguage = "en"` exists as a stored forward hook but nothing reads it on main. (`WhisperKitTranscriptionService.swift:133`; `AppSettings.swift:8`; repo tree)
- NFR-34 **[Implemented]** Where formatting is locale-sensitive it already delegates to the system: dose confirmations use `date.formatted(date: .omitted, time: .shortened)` (locale-aware 24h/AM-PM); recording dates use `RelativeDateTimeFormatter` with `.full` units style. (`DoseConfirmationCopy.swift:22-25`; `Recording.swift:129-133`)
- NFR-35 **[Committed]** Localization target: externalize user-facing strings into a String Catalog and parameterize the transcription language before shipping non-English locales. No infrastructure exists yet; this is a design target, not a 1.0 feature.

## Compatibility

- NFR-36 **[Implemented]** Deployment target is iOS 26.0 (app target and both SwiftPM packages; the design language assumes iOS 26 Liquid Glass). (`project.pbxproj` `IPHONEOS_DEPLOYMENT_TARGET = 26.0`; `Packages/*/Package.swift`; `DESIGN.md` §Product Context)
- NFR-37 **[Committed]** The oldest supported hardware class referenced by engineering comments is A14-family (the export size guard names "the A14 minimum target"). (`ExportService.swift:142-149`)
- NFR-38 **[Implemented]** Audio session configuration supports Bluetooth capture routes: `.playAndRecord` with `[.allowBluetoothHFP, .allowBluetoothA2DP]`. Background mode `audio` is declared. (`AudioRecordingServiceImpl.swift:66-70`; `app-four/Info.plist`)
- NFR-39 **[Implemented]** Simulator compatibility is explicit: fake sine-wave audio levels (0.2–0.8) substitute for metering, and compute units fall back to `.cpuAndGPU`. (`AudioRecordingServiceImpl.swift:43-52`; `ComputeEnvironment.swift`)
