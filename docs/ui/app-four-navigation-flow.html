Navigation & UX Flow

Every screen, push, sheet, cover, alert, and in-view state in the shipping app: how you get between them, and how you get back. Reconstructed from the SwiftUI source (code is the source of truth), not from mockups.

How this was built: two independent agents analysed the codebase in parallel. Analyst A took the navigation-structure lens (TabView/NavigationStack/.navigationDestination/.sheet); Analyst B took the user-journey lens. A third pass then cross-verified both against the code and resolved every disagreement (file:line throughout). Diagram rendered locally with Mermaid → SVG. Generated 2026-07-02. Corrected 2026-07-02 after a second pass by three independent reviewers: Insights day tap-through found dead (never wired), Acknowledgements push restored to the notes, storage-alert title, Log-Dose field order, conditional download-error pills, exporter-failure attribution, and the TESTFLIGHT gate fixed.

Key user journeys

First-run onboarding setup

  1. Cold launch → RootContainerView reads hasCompletedOnboarding == false
  2. Welcome shown as a full-screen cover over the Calendar-rooted TabView
  3. Tap Start → persists completion, dismisses the cover
  4. Lands on the Calendar tab (default), not Check-in
  5. Whisper model downloads in the background, never gating the UI

Voice check-in core loop

  1. Check-in tab (idle) → tap Speak check-in
  2. Disk + mic-permission checks pass
  3. Recording: live timer, rotating prompts, 8-min cap
  4. Tap Stop & save → processing “Saving…”
  5. Success → done “Captured.” (transcription runs in background)
  6. Tap Done → reset to idle

Save-failure recovery unhappy path

  1. processing → save throws → saveFailed overlay (audio buffered)
  2. Tap Try again → re-save the buffer → done
  3. or tap Discard → buffered file deleted → idle
  4. No audio is ever lost; retry never re-records

Text check-in core loop

  1. Check-in idle → tap Type note → composer sheet
  2. Set Mood / Energy / Focus + free-text note
  3. Tap Save check-in → success dismisses → hub shows “Captured.”
  4. On failure: sheet stays open with inline retry, draft intact

Deep-link auto-capture entry

  1. Open whispernotes://checkin
  2. onOpenURL → selectedTab=.checkIn + shouldAutoStartRecording
  3. consumeAutoStart → begins voice capture (never double-starts)

Browse & open (Calendar) read

  1. Calendar → collapsible week/month + DayCard timeline
  2. Tap a day cell in the calendar header → scrolls to and auto-expands that DayCard (tapping a DayCard header toggles it too)
  3. Tap a TimelineRow → path.append(UUID) pushes Recording Detail
  4. Back pops to the day

Open via Insights unwired

  1. Insights → page through 5 sections
  2. Dead end: the Day Detail sheet and the Insights push to Recording Detail are declared (.sheet(item:) + .navigationDestination) but unreachable — nothing ever sets selectedDay, and no day / bubble / bead has a tap handler (onBeadTap is never passed)
  3. Opening a recording currently works only from the Calendar tab

Edit extracted signals correct

  1. Recording Detail → tap pencil → Extraction Review sheet
  2. Adjust When / Mood / Energy / Focus / Sleep / Medications / Emotions / Side-effects (8 fields)
  3. Tap Save → dismisses to detail; Cancel / swipe-down discards

Delete a recording deferred

  1. Recording Detail → tap visible Delete check-in
  2. confirmationDialog → Delete → pendingDelete + dismiss() pops the push
  3. viewModel.delete() runs in .onDisappear, which avoids a SwiftData @Model teardown crash

Log a medication dose meds

  1. Either Check-in idle → Log meds, or tap a dose in the global med-bar → Log new dose
  2. Both open the Log Dose sheet
  3. Pick Medication / Dose / Effect Duration / Taken At (in that order) → Save → dismiss

Manage transcription model settings

  1. Settings → AI Models → the model row
  2. Not installed → download → downloading (progress + Cancel) → installed
  3. On cellular-blocked failure: Try again / Allow on cellular / Open Settings; any other failure shows Try again only
  4. Tap installed → confirmationDialog Delete Model

Encrypted journal export data

  1. Settings → Save a copy of my journal → in-row spinner while preparing
  2. System file exporter
  3. On success → Recovery Key sheet (one-time, never persisted) → Done
  4. On file-exporter failure → “Couldn’t save a copy” alert (a prepare failure never presents the exporter at all)

Architecture notes

  • One TabView, four tabs (Calendar / Check in / Insights / Settings). Each tab wraps itself in its own NavigationStack via ScreenContainer, so there is no app-wide shared stack.
  • Two push targets: RecordingDetailView, via .navigationDestination(for: UUID.self) on the Calendar and Insights stacks (the Insights route is registered but dead — nothing appends to that path), and AcknowledgementsView, via a NavigationLink in Settings. Everything else is a sheet, cover, alert, or confirmationDialog.
  • Dead navigation in Insights: DayDetailSheet and its push chain are fully declared but unreachable — InsightsViewModel.selectedDay has no writer, and no chart element has a tap handler (SignalStripsView.onBeadTap defaults to nil and is never passed). Not an accident: the Insights→detail entry point was explicitly deferred when feature 002 shipped (2026-06-16, BACKLOG); the sheet is scaffolding awaiting that wiring.
  • Check-in is an in-view state machine (idle → recording → processing → done) with saveFailed as a Bool overlay. .paused is a defined RecordingState case that is rendered but never assigned, so it is unreachable via the UI.
  • The medication bar is a global overlay (rendered .card() Paper, not Liquid Glass; the .glassEffect references are stale doc comments) pinned over all 4 tabs and Recording Detail; hidden only on Acknowledgements.
  • Onboarding is a first-run WelcomeView presented as a fullScreenCover gated on AppSettings.hasCompletedOnboarding (skipped under DEBUG mock mode). Deep link whispernotes://checkin switches to Check-in and auto-starts recording.
  • Not in the live graph: FeedbackButton/IssueReportView are retained but unmounted (spec 024; it crashed the app). Test Services (5-tap on the version label) is live in both DEBUG and TESTFLIGHT builds, not DEBUG only.
