## A. Sync mechanism & runtime opt-in (cloudkit + swiftdata)

- **A1 — Mechanism**: SwiftData **native CloudKit mirroring** via `ModelConfiguration(cloudKitDatabase: .private("iCloud.<container>"))` to the user's **private** database. Idiomatic for a 100%-SwiftData app; `NSPersistentCloudKitContainer` (Core Data) and manual `CKSyncEngine` both rejected (rewrite / hand-rolled record mapping for no benefit — reserve `CKSyncEngine` only if custom conflict logic is ever required).
- **A2 — Off-by-default + toggle** ⚠️ **hardest decision, API gap**: there is **no supported live hot-swap** of a `ModelContainer` from local→CloudKit. Off-by-default = ship a **local-only** config (`cloudKitDatabase: .none`) and, on enable, **rebuild** a container from a `.private(...)` config against the *same store URL*. Two ship patterns:
  - **Pattern A — apply-on-next-launch (RECOMMENDED for MVP)**: the toggle writes a preference; the container's `cloudKitDatabase` is chosen from the flag **at launch**. No orphaned contexts, no root re-key, minimal surface. Cost: sync starts after the app is reopened.
  - **Pattern B — live root-swap (deferred)**: container in an `@Observable` holder at the root scene; toggling rebuilds it and re-keys the root subtree. No relaunch, but requires refactoring the app's `static let` container + statically-captured `.mainContext` first (see A2-blocker). Deferred to a later slice.
  - **A2-blocker (real)**: `AppModelContainer.container` is a `static let` and [`AppDependencies`](app-four/Store/AppDependencies.swift#L8) + several view-models capture `.mainContext` at static-init. Pattern B can't work until those read the container through one mutable holder. Pattern A avoids this entirely (the `static let` is computed once at launch from the flag).
  - **Inferred, must device-validate**: that a previously-local store *begins mirroring existing rows* when reopened with `cloudKitDatabase` set (first enable performs an initial export). Well-established for `NSPersistentCloudKitContainer` but not doc-quotable.
- **A3 — Backup exclusion coexists**: keep `isExcludedFromBackupKey` on the store dir while mirroring — file-backup exclusion and CloudKit content-replication are **independent**; this is the correct config (satisfies Constitution VI). Re-apply after container creation (already done at [AppModelContainer.swift:27](app-four/App/AppModelContainer.swift#L27)); exclude the **directory** so WAL/sidecar files are covered.
- **A4 — Account gating**: `CKContainer.accountStatus()` → only enable on `.available`; map `.noAccount`/`.restricted`/`.temporarilyUnavailable`/`.couldNotDetermine` to distinct honest messages; observe `CKAccountChanged`. `accountStatus()` doesn't expose an "iCloud Drive off" boolean — also handle it via write-time `CKError` (A5).
- **A5 — Conflict & errors**: mirroring resolves conflicts **last-writer-wins** (attribute-level; relationship-level LWW+merge), **not customizable** through the mirror (the Core Data `NSMergePolicy` governs *local* saves only). ⚠️ LWW specifics are WWDC/community-sourced, not on the primary reference page. Surface honestly: `.quotaExceeded` ("iCloud storage full — paused"), `.networkUnavailable/networkFailure` (queue + retry), `.notAuthenticated` (→ A4), `.requestRateLimited/zoneBusy` (respect `retryAfterSeconds`), `.partialFailure` (per-item). No silent spinner.
- **A6 — Entitlements**: iCloud capability + **CloudKit** service, `icloud-container-identifiers`, Push (auto-added), Background Modes → **Remote notifications**. ⚠️ The **Stable TestFlight 2nd bundle id** must have the same CloudKit container provisioned or Stable builds fail on container mismatch.

## B. Schema migration & CloudKit-compat (swiftdata)

- **B1 — Dropping `.unique` = LIGHTWEIGHT**: `MigrationStage.lightweight(V1 → V2)`, no custom stage. Only *adding* a unique constraint needs a dedup stage (WWDC23 10195); *removing* one relaxes the constraint → nothing to transform, no wipe (satisfies the v1.2 "no wipe" mandate). ⚠️ "removing `.unique` is lightweight" is inferred, not verbatim — verify V1→V2 against a **copy of a real V1 store** before shipping.
- **B2 — "Stable non-unique UUID" = app-level merge key**: `id: UUID` **loses `.unique`, stays** as a plain attribute. CloudKit can't enforce it, and CloudKit record identity comes from the per-store `PersistentIdentifier` (two devices minting "the same" logical row get *different* record names — never auto-merged). De-dup is **code-side upsert (fetch-by-id → update-or-insert)**. For **deterministic singletons**, derive the UUID so both devices compute the same key: `DayCalendarContext` from the calendar day; `RecordingTag` from the normalized tag name (or match-by-name on merge). User-authored single-origin rows (`Recording`, `MedicationEvent`) use random UUIDs (no cross-device collision) — the upsert is a cheap safety net.
- **B3 — CloudKit-compat audit (reconciled against source)**: rules — (R1) no `.unique`; (R2) every non-relationship attribute optional **or** defaulted; (R3) all relationships optional; (R4) inverse required; (R5) no `.deny` delete rule. **Reconciliation with actual `@Model` source found the audit is larger than "drop `.unique`":**
  - **Recording** (synced): drop `.unique` on `id`; **add inline defaults to ~10 bare non-optional scalars** (`createdAt`, `updatedAt`, `audioFileName`, `duration`, `fileSize`, `status`, `fullTranscriptText`, `title`, `isFavorite`) to satisfy R2; relationships already optional/defaulted with cascade + inverses (`segments?`, `correctionTags?`, `medicationEvents = []`) — confirm `medicationEvents` empty-default is accepted.
  - **TranscriptionSegment** (synced): drop `.unique` on `id`; add defaults to `text`/`startTime`/`endTime`/`isFinal`/`language` (R2); `recording: Recording?` already optional (R3) — **needs an explicit inverse declared** (R4).
  - **RecordingTag** (synced): no `.unique` today; add defaults (R2); `recording?` optional; deterministic key (B2).
  - **MedicationEvent** (synced): already fully inline-defaulted + `recording? = nil` — **CloudKit-shaped already**; only needs its inverse confirmed.
  - **AppSettings, ModelMetadata** (local-only per B4): **no change** — exempt from R1–R5, keep `.unique`.
  - ⚠️ **Constitution IX is latently violated today**: Recording/TranscriptionSegment already fail "optional-or-defaulted." This feature *restores* IX compliance for synced models. Surface to owner.
- **B4 — Selective sync = two configs, one container**: `ModelConfiguration("Synced", …, cloudKitDatabase: .private(…))` + `ModelConfiguration("Local", …, cloudKitDatabase: .none)` in one `ModelContainer`. Supported (Apple Forums 743863). **Hard constraint**: **no cross-configuration relationships** or the stores silently merge — verified safe (AppSettings/ModelMetadata have no `@Relationship`).
- **B5 — Ordering vs. readiness branch**: baseline = `SquirlSchemaV1` + crash-safe container from `fix/app-store-readiness` (must merge first). Then: add `SquirlSchemaV2` (drop `.unique` + defaults + inverses + `.allowsCloudEncryption`), append `.lightweight(V1→V2)`, switch to the two-config container. Migration runs **before** CloudKit validation, so V2 is already valid when `.private` attaches. **Never attach `cloudKitDatabase` to a schema still holding `.unique`/bare-non-optional/non-optional-to-one** — init throws. **Opt-in = toggle the config (`.none`↔`.private`) over a permanently-V2 schema — no re-migration.** **Additive-only after production promotion** — finalize V2 shape before promoting the CloudKit schema. **Fail closed** on migration error, never wipe.

## C. Encryption for E2E (swift-security + cloudkit) — premise corrected

- **C1 — SwiftData CAN do field-level CloudKit encryption**: `@Attribute(.allowsCloudEncryption)` (iOS 17+) maps to CloudKit `encryptedValues`. My earlier "SwiftData API gap" assumption was **wrong**. FR-016 is satisfiable natively.
- **C2 — Native path is primary (matches FR-016 exactly)**: mark `transcript`/med-name fields `.allowsCloudEncryption`. Under **ADP** these marked fields (+ all CKAssets) are **end-to-end** ("not even Apple"); under standard protection they're encrypted but developer-inaccessible with Apple-held keys — precisely FR-016's ADP-conditional wording. **App-level CryptoKit + iCloud-Keychain key** (AES-256-GCM, `SymmetricKey`, `kSecAttrSynchronizable`) is the **escalation path only** — the one thing it adds is E2E for *non-ADP* users, at the cost of C3's dual-store. Not adopted unless "E2E for everyone" becomes a hard requirement.
- **C3 — No search penalty (the deciding advantage)**: `.allowsCloudEncryption` scopes encryption to the **CloudKit mirror**; the **local SQLite replica stays plaintext**, so `@Query`/`#Predicate` over transcripts are unaffected (the "can't query encrypted fields" rule is server-side only). ⚠️ "local stays plaintext" is a consequence, not verbatim doc — device-validate a `#Predicate contains` over an encrypted attribute.
- **C4 — Hard constraints**: encryption state **cannot change after production schema promotion**, and you **cannot encrypt an already-synced field** — so mark all sensitive fields encrypted **before first production promotion**. Sync is new here, so this is free *if done from day one*. If any prior TestFlight build already mirrored these fields unencrypted, introduce **new** attributes + migrate. Relationships (`CKRecord.Reference`) can't be encrypted (fine).
- **C5 — Encryption field set (recommended)**: transcript/health free-text — `Recording.fullTranscriptText`, `TranscriptionSegment.text`, `Recording.medicationInfo`, `Recording.summary`, and the derived-content JSON blobs (`noteExtractionJSON`, `summaryBulletsJSON`, `emotionsJSON`, `sideEffectsJSON`, `sleepEventJSON`, `topicTagsJSON`); medication names — `MedicationEvent.name` (+ `dose`), `RecordingTag.name`. Finalize the exact set in tasks; all must also be optional/defaulted (R2).

## D. App Store compliance (app-store-review)

- **D1 — Label stays "Data Not Collected"**: private-DB sync is developer-inaccessible → fails Apple's "Collect" test ("transmitting data off the device in a way that allows **you…to access it**"). Keep the empty `NSPrivacyCollectedDataTypes` at [PrivacyInfo.xcprivacy](app-four/PrivacyInfo.xcprivacy). Would flip only for public/shared DB, a developer server, or an analytics SDK.
- **D2 — Required-reason APIs: ZERO new**: the three a CloudKit/SwiftData path trips — FileTimestamp `C617.1` (Apple's text names "the app's CloudKit container"), DiskSpace `E174.1`, UserDefaults `CA92.1` — are **already declared**. If sync state moves to an App Group, switch UserDefaults to `1C8F.1`. `NSPrivacyTracking` stays false.
- **D3 — Entitlements are NET-NEW** (no `.entitlements` file exists today): `com.apple.developer.icloud-services = CloudKit`, `icloud-container-identifiers`, Push (auto), Background Modes → remote-notification. **Deploy the CloudKit schema to the Production environment before the first TestFlight upload** (a Dev-only schema is the classic post-approval sync failure). Provision the container for **both** bundle ids (main + Stable).
- **D4 — Review notes** (paste-ready): "iCloud sync is opt-in and off by default. When enabled, data syncs only through the user's own iCloud account via CloudKit's private database; it is not accessible to the developer and no developer server is involved. No account is created — CloudKit uses the user's existing Apple Account, so there are no demo credentials. With sync off, the app is fully functional and local-only."
- **D5 — Health-data guideline risk (5.1.x)**: low — private-DB, on-device-first, developer-inaccessible; opt-in/off-by-default is the primary mitigation (affirmative consent). Keep the privacy policy (in-app + ASC) describing sync. Never store HealthKit-sourced data in iCloud (N/A today — no HealthKit).
- **D6 — Export compliance**: native `.allowsCloudEncryption` = OS-provided + HTTPS → exempt; keep `ITSAppUsesNonExemptEncryption = false` ([Info.plist:5](app-four/Info.plist#L5)). If the app-level CryptoKit escalation is ever adopted, set the key `true` and self-classify as exempt (standard algorithms); a year-end self-classification report may apply.

## Consolidated risk / gap flags (carry into tasks)

1. **No live container hot-swap** → adopt Pattern A (apply-on-next-launch) for MVP; Pattern B (live root-swap) + the `static let`/captured-context refactor deferred. *(A2)*
2. **Latent Constitution IX violation** — Recording/TranscriptionSegment aren't actually CloudKit-shaped today; V2 fixes it. *(B3)*
3. **Encryption is irreversible after production promotion** — mark all sensitive fields before first promotion. *(C4)*
4. **DayCalendarContext (spec 029) is unbuilt** — 038 phase-1 syncs the 4 existing journal models; DCC joins the synced schema when 029 lands (built CloudKit-native from day one, per 029's plan). *(dependency)*
5. **`fix/app-store-readiness` must merge first** (SquirlSchemaV1 + crash-safe container = the V1 baseline). *(B5)*
6. **LWW conflict is fixed/uncustomizable** — acceptable for single-user multi-device; would force `CKSyncEngine` if smarter merges are ever needed. *(A5)*
